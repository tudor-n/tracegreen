# TraceGreen — guide for coding agents

TraceGreen turns a UBL 2.1 e-invoice into a supplier graph with a spend-based CO2e estimate per node, lets a supplier verify a node in two taps through a signed single-use link, and shows a buyer the cost / carbon / lead-time trade-off of a greener choice. Three services behind one browser origin: `api/` (C#, .NET 10, owns every carbon number), `ai/` (Python FastAPI, classifies line items and suggests alternatives, never computes carbon), `web/` (Vite + React SPA, renders only).

Current status and remaining work, in order: `docs/NEXT.md`. Decisions and the review rulings R1–R8: `docs/DECISIONS.md`. How supplier answers are weighed (F7): `docs/TRUST.md`. How it fits together: `docs/ARCHITECTURE.md`. Security controls: `docs/SECURITY.md`. Supplier Terms and their legal basis: `docs/legal/README.md`. Status by roadmap ID: `docs/ROADMAP.md`. How to run: `docs/RUNBOOK.md`. Factor provenance: `docs/factor-sources.md`.

Team plan and briefs: docs/plan/

## Commands

Everything: `docker compose build && docker compose up` (Postgres, API on :8080, AI on :8000, web on :3000 with `/api` proxied). Demo image: `docker compose -f compose.yml -f compose.demo.yml up --build`.

| Service | Run | Test | Lint / typecheck |
|---|---|---|---|
| `api/` | `dotnet run --project src/TraceGreen.Api` | `dotnet test` (one test: `dotnet test --filter-method "*Name*"`) | build has `TreatWarningsAsErrors` |
| `ai/` | `uv run uvicorn app.main:app --reload --port 8000` | `uv run pytest` (one: `uv run pytest -k name`) | `uv run ruff check . && uv run ruff format --check .` |
| `web/` | `pnpm dev` | `pnpm test` (vitest), `pnpm e2e` (Playwright against Compose) | `pnpm typecheck && pnpm lint` |

The host SDK for the API is .NET 10 (`api/global.json`). On Windows it is installed under `%LOCALAPPDATA%\Microsoft\dotnet` — put that directory first on `PATH` or run the commands inside `docker compose exec api`. On Linux install a .NET 10 SDK at 10.0.100 or later (e.g. `sudo apt install dotnet-sdk-10.0`; check with `dotnet --list-sdks`); worktree sessions need it on the host because the container only sees the main checkout.

## Map

- `api/src/TraceGreen.Domain` — pure C#: model records, carbon math (`Carbon/`), UBL parser (`Ubl/`), canonical JSON + hashing + HMAC tokens (`Security/`), the C# copy of the banned terms for model-written text (`Copy/BannedTerms.cs`), audit chain (`Audit/`), plausibility rules (`Plausibility/`: `AIR_HEAVY`, `SEA_TOO_FAST`, `MASS_BELOW_INVOICE`), the supplier trust model (`Trust/`, F7: `TrustAssessor` weighs each answer with its evidence and the buyer's records, gives the counted figure, the kilograms at risk and a 0–100 score; `DocumentIds` and `TaxIds` hold the check digits; `TargetFigure` the best possible state; constants in `TrustPolicy`), classification (`Ai/`: `LineClassification` invoice code → the buyer's earlier review of the same description → cache → AI → stub, `CacheKey`; `IAiClient` and `IAiAssist`, the port for the longer chat and extraction calls), the chat's facts and answer check (`Chat/`), seed loading (`Seed/`: `SeedLoader`, `DemoState`), ports (`Ports/IRepository`, `IEventBus`; `Ai/IAiClient`; `Security/ILinkSigner`), use-case services (`Services/`, configured through `ServiceOptions`; graph, ingest, demo, link, verify, scenario and portal, the supplier page of F12; classification, the buyer's review of an AI-mapped category behind `POST /api/nodes/{nodeId}/classification` (F6: `review` `notNeeded | pending | confirmed | corrected` on `ClassificationView`, source `Buyer` after a review, audit `classification.reviewed`, then `node.updated`); suggestion (F11), chat (F13) and PDF import (F9, with its in-memory draft store); trust (F7: `TrustService` for the buyer's records, a person's decision on a claim and the target; `LinkOriginStore` keeps the keyed hash of who made each link, in memory); `NodeFactory` builds nodes for the seed and for imports alike). No package references.
- `api/src/TraceGreen.Infrastructure` — adapters: `Memory/` (in-memory repository + event bus), `Postgres/` (EF Core + Npgsql, migrations), `Ai/` (HTTP client to the Python service, stub).

- `ai/app` — FastAPI (`main.py`, `create_app`): `POST /classify` through the chain cache → the models in `AI_MODELS`, in order → stub, one batch per call within `AI_TIMEOUT_S` (8 s), with the allow-list enforced and answers below 0.6 confidence turned into `UNCLASSIFIED` (`providers.py`, which also keeps model answers in an in-memory runtime cache); `config.py` parses `AI_MODELS` into model specs, each with a ready flag and a reason; `models.py` builds the LangChain chat models lazily (temperature 0, no retries, a timeout per model); `prompts.py` holds the system prompt with the allowed categories and puts invoice lines in an `<invoice_lines>` block as data; `POST /classify?model=<id>` exists only with `AI_DEV_ROUTES=1` (scoring); `POST /suggest` (`suggest.py`: picks among the curated alternatives the API sends, under short ids; a reason with a digit or a claim word is dropped), `POST /chat` (`chat.py`: one or two sentences citing the facts the API sends by id, the cheap checks mirrored; a `model` from `GET /chat/models` answers alone, an unknown or unready one is 422; `local_models.py` lists the Ollama server's models for the picker, `OLLAMA_DISCOVER`; every Ollama call gets one `OLLAMA_NUM_CTX`), `POST /extract-pdf` (`pdf.py` reads the text layer with pypdf under caps and a deadline, `extract.py` has a model copy the fields into a fixed schema and `evidence.py` marks each field found or not in the text; nothing is imported there); `structured.py` is the one structured model call every task shares (`ask_once`, `first_valid`, `bind_models`, `call_with_deadline`), `GET /health` (with `models`); `schemas.py` is the camelCase contract `HttpAiClient` sends and reads; `cache.py` keys `seed/ai-cache.json` exactly as `Domain/Ai/CacheKey.cs`. ## Invariants

- Product name is TraceGreen; the string "VerdantFlow" must not appear anywhere.
- Pin exact versions (`Directory.Packages.props`, `uv.lock`, `pnpm-lock.yaml`, no `^`/`~`); do not upgrade before 2026-11-08; note any new dependency here. CI actions are pinned to release commits in `ci.yml`: `actions/checkout` v7.0.1, `actions/setup-dotnet` v6.0.0, `actions/setup-node` v7.1.0, `pnpm/action-setup` v6.1.0, `astral-sh/setup-uv` v10.3.0 (uv 0.13.3, as in `ai/Dockerfile`).
- Dependencies added for F6 in `ai/pyproject.toml`: `langchain-core` 1.7.0, `langchain-anthropic` 1.7.6, `langchain-openai` 1.7.2, `langchain-google-genai` 4.4.2 and `langchain-ollama` 1.1.0, beside `anthropic` 1.15.0, with `[tool.uv] exclude-newer = "2026-10-24T00:00:00Z"`. Lock with `UV_PYTHON=3.12 uv lock` (the default Python 3.15 fails to build `orjson`). Added for F9: `pypdf` 6.21.2 (pure Python, no dependencies of its own; reads a PDF invoice's text layer in `ai/app/pdf.py`). After pulling a dependency change, run `docker compose up --build --renew-anon-volumes`.
- Every feature works in both `DATA_MODE=memory` and `DATA_MODE=postgres`; both repositories are seeded through `IRepository.SeedAsync` and pass the same contract tests.
- Carbon math is server-side C# only; every factor lookup returns value + unit + source + year + row label; every division is guarded (a MAC with zero or negative carbon saving is "not an abatement option", never infinity). `decimal` for money and kilograms; kg internally, tonnes with two decimals in UI (a gap or change between two figures on screen is worked out from the figures as shown, so they agree), euros without decimals, days as integers.
- Node status is `ESTIMATED | PARTIAL | VERIFIED`; the hotspot ring is a derived overlay.
- The AI never produces a carbon number. Categories outside the allow-list become `UNCLASSIFIED`. Invoice text, facts, questions and candidates are passed as delimited data. The API calls the AI service with a 10 s timeout for classification and suggestions and falls back to the stub; ingest never blocks on AI. The chat (F13) and PDF extraction (F9) have their own budgets (`AI_CHAT_TIMEOUT_MS`, `AI_EXTRACT_TIMEOUT_MS`) on a separate client. Every AI-derived value in the UI is labelled (`AI-mapped`, `AI-suggested · illustrative`, `AI-extracted · check fields`, `AI-written · values from your data`, `AI-written · general, no values from your data`; a buyer's category reads `Category set by buyer`); lane costs and lead times are labelled illustrative.
- AI-extracted fields (the PDF import, F9) are confirmed by a person before ingest; the server holds the draft and the audit entry records which fields the person changed. The customer is always the workspace's buyer.
- The chat's model cites every value and name as a `{{factId}}` placeholder; the API fills the values in from its data and `Domain/Chat/AnswerCheck.cs` refuses typed numbers and names, unknown facts, claims the facts contradict and claims about the data that cite no fact; a general answer (help, terms, advice) may cite none. It also refuses a change described the wrong way ("cut" with a positive change), a promised action ("I'll add a what-if": the assistant only reads), the same value twice in a sentence, a what-if or figure under another supplier's name, and a supplier sent to a mode none of its what-ifs offer. The facts include the simulator's what-ifs for the largest suppliers (`FactPack` W facts, signed, never saved). A refused answer goes back to the model once with the rule (`AnswerCheck.RetryHint`), and a long one may be shown without its one false sentence (`AnswerCheck.Trim`). Never show a model's sentence that did not pass it. An AI suggestion picks among curated alternatives only; a reason with a digit or a claim word is dropped.
- The AI service tries the cache, then each model in `AI_MODELS` within one 8 s budget (`AI_TIMEOUT_S`; at most `AI_MODEL_TIMEOUT_S` 4 s per cloud model and `OLLAMA_TIMEOUT_S` 6 s for the local one), then the stub, so it answers before the API's 10 s timeout. Model keys live only in the server env (the root `.env`); a model without its key is skipped and `/health.models` says why. Model answers go through the allow-list, the 0.6 confidence threshold and the line-id check before the API sees them.
- Verification tokens are `v1.`-prefixed HMAC-SHA256, expiring, bound to the invoice content hash; single use is enforced by the repository's unique nonce. Replay → 409, expired or hash mismatch → 410, bad signature → 401, rate limit → 429. Tokens never appear in logs or audit payloads. Supplier page tokens (F12) are `p1.`-prefixed with their own derived key and reusable until they expire; every answer from that page still goes through a fresh single-use `v1.` link.
- A supplier answer needs the Supplier Terms, on `/verify/*` and on `/supplier` alike: the supplier ticks an unticked box, the submit carries the terms' SHA-256 from the context (else 422 `TermsNotAccepted`), and the verification row and audit payload record the version and SHA-256. Never pre-tick the box. A published version of `seed/supplier-terms.json` is never edited; a change gets a new `version` and a new line in `seed/supplier-terms-versions.json` (`node scripts/terms-hash.mjs` prints it), and the seed refuses to load otherwise. Its `[PLACEHOLDER: …]` operator details stay visible until a person fills them in, and the preflight fails meanwhile.
- `audit_log` is append-only and hash-chained from a genesis hash of 64 zeros; never update or delete rows.
- No `dangerouslySetInnerHTML` (lint error). No cookies, login, email, camera or clipboard APIs on `/verify/*` or `/supplier`. Secrets only in server env; never commit `.env` or `.env.*.local` (`.env.demo` is committed on purpose and is demo-only).
- LF line endings; scripts are Node `.mjs`, PowerShell, `dotnet` or `uv` entry points — no `.sh`.
- Commit subjects reference feature or control IDs, e.g. `F3: single-use token check`. No attribution trailers.

## Copy rules

For anything a person outside the team can read: UI strings, seed data, README, demo copy, OpenAPI descriptions and the public docs. `scripts/lib/banned-terms.mjs` enforces the terms through the copy-guard hook and the preflight; this file is exempt so it can name them.

- KPI wording (ruling R2): the API field is `primaryShare`; the UI says "Supplier-confirmed share", subtitle "by emissions, not by node count". Never write "primary data" without that definition, never "verified PCF", never "blockchain" (say "tamper-evident audit log"), never "first" or "only".
- Never a real company name. The seed stays fictional: Transilvania Electro-Assembly SRL and its five suppliers. The banned names are stored only as hashes in `banned-terms.mjs`; add new ones with its `--hash` / `--exact` flags, never in plain text, and copy the same entry into `api/src/TraceGreen.Domain/Copy/BannedTerms.cs` (the API's check of model-written text; `BannedTermsTests` fails until both lists match).
- Provenance on every node (ruling R3): "Supplier-confirmed · <factor source> <year>" when VERIFIED, "Spend-based estimate · <factor source>" when ESTIMATED; lane cost and lead time say "illustrative".

## Data rules

- Never put a number into `seed/factors.json`, a lane, a mass or `ETS_PRICE_EUR_PER_T` that a person did not take from a named source. A row's `source` keeps its PLACEHOLDER text until a person replaces the row with one that names the table, year and row label (`docs/factor-sources.md`). A PLACEHOLDER source stays visible on screen.
- Never hand-tune demo numbers to make a badge appear. If real factors change a badge, report it in `docs/NEXT.md` and change what the demo script says (`docs/RUNBOOK.md`, "Demo steps (F1–F4)"; D5).
- No cloud deployment, tunnel or new dependency until the simulator slice is done; the demo runs on the laptop's hotspot (ruling R6).

## Working style

Deliver what was asked at the scope intended; make routine judgment calls yourself and check in only when readings would lead to materially different work. Finish the whole task and say plainly what is missing if something cannot be done. Lead with the outcome when reporting; write complete sentences a teammate can follow without your context. Run the real commands (tests, lint, Compose) instead of adding self-check prompts or verification scaffolding. Use subagents only for sizeable independent tracks, never to verify your own work.
