# Decisions

The ledger of decisions you would not guess from the code. Each line reads **decision** — reason — cost if wrong. To override one, edit its line and add the date and the reason. Current status and the work still open: `docs/NEXT.md`.

IDs: `F#` features, `C#` controls, `T#` tasks and `M#` milestones are the roadmap's (`docs/ROADMAP.md`); `R1`–`R8` are the rulings of the 2026-10-22 code review; `D1`–`D6` are the team's open questions from `docs/plan/README.md`; `A#`, `B#`, `C#` tasks are in `docs/plan/dev-{a,b,c}.md` (the C prefix is shared by controls and Dev C's tasks; the context says which).

## Stack and shape

- **C# .NET 10 API, Python FastAPI AI service, Vite + React SPA, one browser origin** — every carbon number stays in one typed, tested place; the AI service is replaceable; the browser and the phone talk to one origin — cost if wrong: a service rewrite.
- **Carbon math is C# only; the simulator is a stateless endpoint** — the UI and the AI never compute carbon, so a number on screen always has a server-side source row — cost if wrong: none known.
- **Postgres in Docker through EF Core, not a local Supabase stack; the migrations include row-level security** — one Compose file runs everything offline, and hosted Supabase stays possible — cost if wrong: a migration to a hosted database.
- **Services live in `TraceGreen.Domain/Services` and read a Domain-side `ServiceOptions` record that `Program.cs` builds from `AppConfig`** — the Domain keeps no project or package reference and the services are testable without a web host — cost if wrong: moving a few classes.
- **A `workspace_id` column and a `Ctx(WorkspaceId, Actor)` argument exist from day one** — authentication later is a policy, not a refactor — cost if wrong: one column.
- **`dotnet watch` is not used in Docker** — its polling watcher crashes on Windows bind mounts; the API container runs `dotnet run`, and a C# edit needs `docker compose restart api` — cost if wrong: slower edit loop only.

## Wire contract, slice 1 (A1–A3)

- **`NodeView` is the one node shape on the wire**, in the snapshot and in every node event (`Domain/Model/ReadModel.cs`, built by `NodeViewMapper`): `carbonKg` with its `basis` (`spend` or `activity`), both figures with their `FactorLookup` rows (the "i" icon; a PLACEHOLDER source reaches the screen), R4's `uncertainty`, `classification` (source, confidence, `aiMapped`), an `invoice` summary and the `lane` (`illustrative: true`). PARTIAL stays on the spend figure; `carbonKg` switches to activity only when VERIFIED — one shape means one reducer in the store — cost if wrong: a second type.
- **Event types reach the generated client by describing `/api/events` as `text/event-stream` of `DomainEvent`**, a union discriminated by `type` (`node.created`, `node.updated`, `node.verified`, `audit.appended`, `scenario.saved`, `graph.reset`), written first and equal to the SSE event name; `hello`, `resync` and `ping` carry no domain data; `node.verified` carries a `VerificationView` without nonce or address hash — nobody hand-writes API types — cost if wrong: hand-written event types.
- **One JSON shape for responses and SSE (`ApiJson`)**: camelCase, enums as camelCase strings (error codes and node status keep their spelling), numbers never as strings, constructor parameters required, nullability as annotated — the generated types have no spurious optional fields — cost if wrong: client-side guards.
- **Enum components hold only their values**: a schema transformer removes the `null` .NET folds into an enum the first time it meets it as nullable; nullable properties say so themselves — so `Record<EnergySource, string>` typechecks — cost if wrong: casts in the SPA.
- **An optional request field needs a default (`= null`)** — `ApiJson` treats required constructor parameters as required for requests too, and an omitted one gets a bare 400 without an `ApiProblem` code — cost if wrong: a confusing 400.
- **Errors are `ApiProblem`** (RFC 9457 fields plus a typed `code`); clients switch on `code`, never on titles — cost if wrong: brittle error handling.
- **The snapshot reads `lastSeq` before the nodes, and the store applies events idempotently** (upsert by id, skip known audit entries, ignore `seq <= lastSeq`) — an event published while the snapshot is built is newer and applied on top, even when it repeats what the snapshot shows — cost if wrong: a missed or doubled update.
- **An event that cannot be serialised becomes `resync`** on the stream — the client refetches instead of the stream breaking on every replay — cost if wrong: none.
- **Client transport (A3)**: `openapi-fetch` typed by `schema.d.ts`; `useGraphEvents` runs the pure `graphSync` reducer: snapshot on every stream (re)open, on `resync`, on `graph.reset` and on a sequence gap; every new request drops the event buffer; stale `seq` is dropped; while the stream is down `/api/graph` is polled every 5 s; a request past 8 s counts as failed; after an API restart the snapshot's lower `lastSeq` wins — cost if wrong: a stuck dashboard.
- **Factor rows on a node come from today's `factors.json`; stored kilograms are not recomputed** — after changing factors, reset the demo; a row that no longer exists is left out of the list instead of failing `/api/graph` — cost if wrong: persist rows on the node.
- **Mass unknown means no activity figure** — the node stays on the spend figure, and a VERIFIED one shows `uncertainty: medium` — cost if wrong: a misleading 0 kg.
- **`baseUrl` is a display hint, not a trusted value** — for forwarded headers the last value wins, but a direct caller can still choose them; it is never written into audit payloads — cost if wrong: a wrong link on the QR card, nothing more.
- **Non-EUR invoices are rejected (`UnsupportedCurrency`); a supplier country without a lane is rejected (`NoLane`)** — the conversion table holds USD/EUR only, and lanes are never invented (CN → `CN-RO`, TW → `TW-RO`, DE → `DE-HH-SB`, RO → `RO-SB-SB`) — cost if wrong: two rows of data.
- **Ingest refuses input it cannot estimate safely, with 422 `Schema`**: nesting deeper than 64 levels (checked by a streaming pass before any tree is built), a total not positive or above 10¹² EUR, a line amount above 10¹², a negative quantity or one above 10⁹ — the bounds keep every later sum inside `decimal`, so one hostile invoice cannot break `/api/graph` for everyone — cost if wrong: returns are rejected until supported.
- **Duplicates are refused by the repository under the same lock as the insert** (raw XML hash, invoice id or node id) — two identical uploads at the same instant give one 201 and one 409 — cost if wrong: duplicate nodes.

## Wire contract, slice 3 (A5–A6)

- **A used link answers 409 on the context route too** — scanning it again shows "already used" before any tap; a submit checks the nonce before it validates answers; the repository's unique nonce stays the guarantee (five concurrent submits: one 200, four 409) — cost if wrong: a confusing second scan.
- **Check order follows the signer: format → signature (401) → expiry (410 `LinkExpired`) → invoice hash recomputed from the stored extract (410 `InvoiceChanged`) → single use (409)**; the node id is read from the token first, unauthenticated, only to load that hash — a genuine link for a node a reset removed is 410; a forged token naming an unknown node still fails its signature — cost if wrong: a wrong status code.
- **A verification rebuilds the node through `NodeFactory` with the answers** — the activity figure, cost and lead time follow the confirmed mode, and a confirmed `massT` replaces the invoice mass; a VERIFIED node can be answered again with a new link, each answer a new verification row — cost if wrong: stale cost and lead time.
- **Audit payloads**: `link.requested {nodeId, expiresAt}` and `verification.submitted {nodeId, verificationId, status, transportMode, energySource, massTConfirmed, warnings, termsVersion, termsSha256}` (the last two since the supplier terms, see below); no token, nonce or address. The verification row stores an address hash keyed from `LINK_SECRET`, never the address — cost if wrong: personal data in an append-only log.
- **Rate limit: ASP.NET Core's fixed one-minute window, `RATE_LIMIT_PER_MIN` (10) per client address on the context and submit routes; the 11th call is 429** — the address is `X-Forwarded-For` only when the peer is in `TRUSTED_PROXIES` (default loopback and `172.16.0.0/12`), `ForwardLimit = 1` — a phone on the hotspot cannot choose its bucket — cost if wrong: one config value.
- **Tokens stay out of logs**: the hosting diagnostics logger is raised to Warning (its request line carries `?t=`), pinned by a test; nginx logs `$uri` without query or referrer, and `/api/verify/context` keeps only critical errors. Not fixed: the Vite dev server prints the full URL on a proxy error; the demo image uses nginx — cost if wrong: a token in a log.

## Supplier terms (F3, 2026-11-06)

The legal reasoning, the clause-by-clause notes and the checklist for a lawyer are in `docs/legal/README.md`.

- **The supplier ticks the Supplier Terms before a submit, and the API refuses a submit without them (422 `TermsNotAccepted`)** — the terms protect the operator against false supplier answers, and a liability limit, a choice of law and a choice of court need express acceptance (Civil Code art. 1203), so the box starts unticked and names sections 6, 7 and 10. The fastest path on the phone becomes two taps (tick, submit) — cost if wrong: one tap.
- **The API owns the text (`seed/supplier-terms.json`) and its fingerprint: SHA-256 of the file's canonical JSON, computed when the seed loads** — the audit row binds an acceptance to the exact words the server served, and a phone on plain-http LAN has no `crypto.subtle` to hash anything itself. The context carries the checkbox statement in both languages with the version and SHA-256 (`VerifyTerms`), so the RO/EN toggle needs no request; the full text is `GET /api/terms/supplier`'s. `web/src/copy/verify.ts` holds the frame strings (version label, "opens in a new tab", the tick hint), not the terms — cost if wrong: the text moves to `copy/` and the hash becomes a pinned constant with a test.
- **The fingerprint can be recomputed without .NET: `scripts/terms-hash.mjs` implements the canonical JSON (keys by UTF-16 code unit, .NET's default string escaping), and `CanonicalJsonAndHashingTests` and `scripts/lib/terms-hash.test.mjs` pin the same probe to the same output** — section 9 lets either party prove the contrary, which needs a check outside the operator's code; CI runs the script tests in the web job — cost if wrong: none.
- **Check order on submit: token → single use → terms → answers** — a used link still says "already used" whatever is sent, and nothing a supplier said is recorded without the terms — cost if wrong: a status code.
- **The verification row (`terms_version`, `terms_sha256`, nullable) and the `verification.submitted` payload record what was accepted** — the seed's verifications predate the terms and carry none — cost if wrong: none.
- **`POST /api/dev/simulate-answer` accepts the current terms on the simulated supplier's behalf, and its `verification.submitted` payload carries `simulated: true`** — the route exists with `DEMO_TOOLS=1` alone and its audit rows otherwise match a real answer's, but the log is the evidence of acceptance (terms section 9), so it never shows the demo tool's answer as a person's — cost if wrong: none.
- **The printable terms live at their own address, `/terms/supplier` (`GET /api/terms/supplier`), without a token and outside the verify rate limit** — the text can be printed or saved before acceptance (CJEU *El Majdoub*), and a printout of the supplier page would carry the link's token in the browser's footer — cost if wrong: none.
- **On the phone the terms sit behind a link: one checkbox whose statement makes the words "Supplier Terms" the link to `/terms/supplier` (new tab); the statement is stored as `acceptance { before, link, after }`** — dev A asked for a shorter page on 2026-11-06; the statement still names §6, §7 and §10, and the full text stays one tap away and printable before acceptance — cost if wrong: the key points or an inline panel come back.
- **Version `2026-11-06` was reworded (a shorter statement, split for the link) before the branch merged and kept its version** — no supplier outside the team had accepted it, so nothing recorded under that fingerprint refers to real use; from the merge on, a change gets a new version — cost if wrong: test acceptances in a dev database carry the earlier fingerprint.
- **Terms that change while a supplier page is open end on `termsChanged`; its retry loads the context again with the box unticked and keeps the supplier's answers where the link still offers them** — the supplier reads the new statement before accepting it, and a retry never swaps their answers for the defaults — cost if wrong: none.
- **A published version is never edited; a change gets a new `version`, and `seed/supplier-terms-versions.json` pins each version to its SHA-256, so the seed refuses to load an edited text under an old version (`node scripts/terms-hash.mjs` prints a new entry). The operator's identity is `[PLACEHOLDER: …]`, visible on screen, and `scripts/preflight.mjs` fails while it remains** (the team's choice on 2026-11-06) — cost if wrong: one more blocker on `v0.9-prehack` until a person names the operator.
- **The migration `SupplierTerms` is hand-written with its model snapshot entries, like `Rls`** — no `dotnet-ef` on the Linux host or in the API container; the Postgres contract run applies it with no pending model changes — cost if wrong: none.

## AI classifier chain (F6, 2026-11-06)

The "Fixed agreements" of the F6 plan (`docs/plan/ai-f6.md`), built in `ai/app`. Set-up and checks: `RUNBOOK.md`, "AI models".

- **The chain is cache → the models in `AI_MODELS`, in order (two cloud models, then a local model through Ollama: `ministral-3:3b`, chosen in Phase 2 in place of the plan's Qwen 3.5) → stub, with one batch per call** — the cache answers known lines offline and for free; a second cloud provider covers an outage or a missing key; the local model covers a venue without internet (ruling R6: the demo runs on the laptop's hotspot); the stub keeps `/classify` answering whatever fails. The order is configuration, not code — cost if wrong: an env change.
- **The local model is `ministral-3:3b`, not the plan's Qwen 3.5 (decided in Phase 2, 2026-11-06)** — the dev machine's Ollama 0.23.4 cannot pull `qwen3.5:4b` (Terminal B's note in `docs/ai-eval.md`); `ministral-3:3b` scores 80% on the 30 Romanian lines (`docs/ai-eval.md`) and answers one demo invoice in under 3 s once loaded. It is weak on connectors (0%) and followed one injection line once, so it stays the last model before the stub, and the demo does not depend on those cases — cost if wrong: one `AI_MODELS` entry.
- **One 8 s budget per `/classify` (`AI_TIMEOUT_S`), with at most 4 s per cloud model (`AI_MODEL_TIMEOUT_S`) and 6 s for Ollama (`OLLAMA_TIMEOUT_S`); each model call runs in a worker thread with a hard deadline, and the next model gets only the time left** — the API gives up at 10 s (`AI_TIMEOUT_MS`), so the service must answer first, if only with the stub. When both cloud models hang, the local model can be left with no time and the stub answers; offline, the cloud calls are expected to fail fast and leave the budget to Ollama (not timed yet) — cost if wrong: env values, tuned through env only.
- **An answer below 0.6 confidence becomes `UNCLASSIFIED` with the rationale "Low confidence, check this line"** — a wrong category silently picks a wrong spend factor, while `UNCLASSIFIED` is visible and asks a person to look — cost if wrong: one constant.
- **Model output is checked like invoice text: only line ids that were sent count, and only the first answer per id; confidence is clamped to 0–1; the rationale is capped at 200 characters; `categoryId` is limited to the allow-list by the output schema and again by the allow-list check** — the C# side checks the allow-list once more (`EnforceAllowList`) — cost if wrong: none.
- **Model answers are kept in an in-memory runtime cache under the same key as `seed/ai-cache.json` (`cache_key` of the description), up to 5,000 entries** — the same description is never sent twice, so a reset and re-import costs no model call and gives the same answer; the cache is lost on restart and never written to `seed/ai-cache.json`, which stays curated by people. A low-confidence or outside-the-list answer is kept too, as `UNCLASSIFIED`, so that line is not asked again until a restart — cost if wrong: a stale answer until a restart.
- **`POST /classify?model=<id>` exists only with `AI_DEV_ROUTES=1`: it skips the cache, asks that model alone, names it in `provider`, and answers 400 for an unknown or not-ready id; with the flag off the parameter is ignored** — scoring each model on the same lines (`scripts/ai-eval.mjs`) needs one model at a time and no cache; the flag is off by default and stays off for the demo — cost if wrong: none on the demo path.

## Supplier trust (F7, 2026-11-06)

The trust model of `docs/TRUST.md`: what an answer must have before its reduction counts, and how a person reviews it.

- **Asymmetric trust: a claim that raises the figure is taken as given; a claim that lowers it counts once something backs it, and until then the counted figure keeps the claim's fallback (the lane's default mode, grid power, the larger of the invoice's and the confirmed mass)** — most suppliers are not obliged to answer, and two taps could cut a figure by 40% (renewable) or about 15× on transport (sea for air on CN-RO) with nothing to check them; nobody lies upward, so raising claims need no proof — cost if wrong: one rule in `TrustAssessor`, and the figures follow.
- **A node keeps three figures: the spend estimate, the supplier's activity figure as answered (`activityKg`) and as counted (`countedKg`), and a target; a VERIFIED node's `carbonKg`, the totals and the KPIs use the counted one** (the user's idea of 2026-11-06) — the estimate stays visible beside the supplier's figure, the gap between answered and counted is what is at stake, and the target shows the way down. The status set and ruling 2's supplier-confirmed share are unchanged — cost if wrong: which figure `SupplierNode.CarbonKg` returns.
- **The counted figure is stored on the node, computed by `NodeFactory` through `TrustAssessor`, and the mapper explains it with the same call** — the KPIs read a stored number, and every rebuild (an answer, a classification review, a buyer's record, a decision) recomputes it from the same inputs, so the explanation never disagrees with the figure. A row written before the migration has no counted figure and counts as answered until the demo is reset — cost if wrong: none.
- **Renewable power without a certificate type and id counts as grid** — the GHG Protocol's Scope 2 quality criteria require an instrument for a market-based claim, and the 40% cut is the largest single lever a supplier holds — cost if wrong: one level in the assessor.
- **Documented claims (a valid id that fits the mode, or a certificate) count; they are not proof, and S2 samples them for a follow-up request** — a check digit stops typos and most made-up numbers, and the id is on record under the Supplier Terms in the tamper-evident log; asking for the document every time would stop the answers — cost if wrong: `TrustPolicy.Counts`.
- **The buyer's own records outrank the supplier's documents: the customs declaration's mode at the border and the transit time from dispatch to receipt can corroborate or contradict the mode** — for an import the buyer is the importer and holds the declaration, an authority record the supplier does not control.
